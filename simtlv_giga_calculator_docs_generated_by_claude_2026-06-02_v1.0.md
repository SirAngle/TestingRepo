## 1. What this is

An internal sales/ops terminal for SimTLV resellers. It compares SIM plan prices across SimTLV's catalogs, mints customer-ready checkout links, builds multi-item orders, and manages topups for existing cards. The UI is Hebrew, RTL throughout — this is non-negotiable and every layout decision assumes it.

The entire application is **one self-contained HTML file**. There is no build step, no bundler, no framework, no server, and no external dependency beyond two Google Fonts (`Suez One`, `Assistant`). The operator runs it from disk (`file://`) or any static host. All state lives in the browser's `localStorage`. This single-file constraint is deliberate (the file is distributed by hand to staff) — do not split it into modules unless the distribution model changes.

Everything network-facing talks to two SimTLV hosts:

* `https://app-link.simtlv.co.il` — the JSON data API (catalogs, zones, prices).
* `https://app.simtlv.co.il` — the customer-facing app; the calculator only *builds links* into it, always carrying the referral code.

**The referral code `R41IMUNU` must appear on every customer-facing URL the tool produces.** It is currently hardcoded at each URL-construction site. If it ever changes, grep for it — there are several occurrences (direct payment links, topup URL rewriter, checkout builder).

## 2. File anatomy

The HTML file has four zones, in order:

1. **`<style>` block** (~400 rules). Organized in layers: base reset → design tokens (`:root` custom properties) → component styles → an appended **"v4 density layer"** near the end that intentionally overrides earlier rules. Ordering matters (see §10 on CSS gotchas). Do not reorder blocks casually.
2. **Shell HTML.** The static skeleton: top bar (brand, country search, selected chips, option toggles), the tab bar, `#results` (all dynamic content renders here), the cart FAB + slide-in drawer, and the quote-template modal.
3. **Small shell `<script>`.** Defines `window.__renderEmptyCart`, `toggleCartDrawer`, `__updateCartFab` — helpers the main script calls but that must exist before first paint.
4. **Main `<script>`** (~190 top-level functions). Constants and state, data loading, render functions, business logic, persistence. Everything is global-scope classic script — no modules, no `type="module"`. Top-level `let`/`const` bindings are **not** on `window`; tests reach them via `window.eval`.

Rendering model: **full re-render.** Nearly every state mutation calls `renderAll()`, which rebuilds the active tab's HTML into `#results` via template strings, updates the cart drawer and FAB badge, then persists the session. There is no virtual DOM and no incremental update; renders are cheap because only the active tab is built. Two exceptions avoid focus-stealing re-renders: typing in the ICCID field and in the batch textarea update state without re-rendering.

Event wiring is inline (`onclick="..."` in template strings). When passing URLs or other strings into inline handlers, the established pattern is `onclick='fn(${escapeHtml(JSON.stringify(value))})'` — JSON for JS-escaping, `escapeHtml` for attribute-escaping. Follow it; hand-rolled quoting has caused bugs before.

## 3. Data sources (SimTLV API)

All five endpoints are GET, no auth, JSON.

| Endpoint | Purpose | Consumed fields |
|---|---|---|
| `/get-countries` | Master country list: USD credit price + **general zone** | `data[]`: `iso_code`, `country_name`, `hebrew_name`, `zone`, `price` |
| `/get-physical-countries` | pSIM country list with **its own zones** | `iso_code` (or `iso`), `zone`; wrapper may be `data[]` or bare array |
| `/get-payasugo-countries` | eSIM country list with **its own zones** | same as above |
| `/get-packages?zone=N` | eSIM gigaboost plans for zone N | `data` (GB), `price` (USD), **`id` = the token segment of the direct payment URL** |
| `/get-physical-packages?zone=N` | pSIM gigaboost plans for zone N | `data_amount` (e.g. `"10GB"`), `price` (ILS), **`id` = numeric URL segment** |

**The three-zone model is the single most important data concept.** A country carries `zone` (general, from get-countries — drives credit tables, the בסיסי grouping, and topups), `esimZone`, and `physicalZone` (from the dedicated lists, falling back to the general zone if a country is absent from a list). These genuinely differ per country — Singapore has been observed as general/eSIM zone 3 but pSIM zone 2. Any feature that prices or links a plan must use the zone matching its SIM type. When multiple countries are selected, the operative zone is always the **highest** per-type zone among the selection.

At boot, `init` fetches the three country lists plus all 20 zones of both package endpoints in parallel, then builds the `data[]` country model:

```js
{ iso, name: {en, he}, zone, esimZone, physicalZone,
  credit_price_per_gb, plans: { esim: [...], physical: [...] } }
```

### Direct payment URL patterns (verified against the live API)

```
eSIM :  https://app.simtlv.co.il/{ISOs}/{gb}gb/esim/{token}?ref=R41IMUNU
pSIM :  https://app.simtlv.co.il/{ISOs}/{gb}gb/physical/{id}?ref=R41IMUNU
Generic chooser (customer picks): https://app.simtlv.co.il/{ISOs}?ref=R41IMUNU
```

`{ISOs}` supports multiple countries, comma-joined and URL-encoded — `DE%2CEG`. The token/id comes from the package entry of the zone that priced the card. Builders: `buildOrderLink(type, gbAmount)`, `buildGenericAppLink()`. Both fall back to a legacy constructed URL if a package has no `id`.

Checkout URLs of the WooCommerce flavor (`simtlv.co.il/checkout/?add-to-cart=…`) appear in the topup flow and the manual-site scans. Their query grammar: `fly_countries` uses **pipe** separators (`KH|VN`) — never commas; `country_name_in_region` carries pipe-joined Hebrew names; `your_iccid`, `quantity`, `empty_cart` as expected.

## 4. Critical business rules

These encode expensive lessons. Breaking any of them produces wrong orders, not just wrong pixels. Each is enforced somewhere in code and most are pinned by a regression test (§8).

**Deal bundles never receive a quantity multiplier.** A "deal" (זוג) checkout URL points at a *bundle product* that already contains the full quantity. Appending `quantity=2` orders two bundles — four SIMs billed as two. Enforced in `buildOrderItemUrl` (passes qty 1 for `source === "deal"` / `isBase === false`) and in the topup deal buttons. If you touch anything in the order pipeline, re-run the suite; this is the most financially dangerous regression in the codebase.

**V1 pSIM topups always use `fly_countries=REUP`.** Never a literal country code. Enforced in `rewritePhysicalTopupUrlForSelected` and belt-and-suspenders in `buildTopupCheckoutUrl`.

**V2 pSIM topups use the selected ISOs**, sorted, pipe-joined — never the zone-probe representative country. Historic bug: the V2 catalog is scanned once per zone via a representative country (alphabetically first — e.g. UZ for a US-zone scan), and that probe ISO used to leak into customer URLs.

**Topups operate on the highest-zone selection only.** `getSelectedTopupCountries()` filters to the top general zone, mirroring how base plan cards behave with mixed-zone selections.

**Cart lines are keyed `${packageKey}::${iccid}`.** Same package + different customer ICCIDs = separate lines (multi-card topups); same package + same ICCID = update in place. `buildOrderItemUrl` applies each line's own `topupIccid`.

**The order runner uses exactly one named background window** (`simtlv_bg_runner`), opened synchronously inside the click gesture and *re-navigated* per item. Browsers allow one popup per gesture; the previous N-windows approach silently dropped middle items on 3+ item orders. `empty_cart=true` goes only on the first item's URL. If the single window is blocked, the runner aborts with an explanatory alert rather than placing a partial order.

**Copy format** for all price lines: `3 גיגה – 30 ימים – ₪55` — en-dash separators (`–`, U+2013), ₪ *before* the number. Price-list copies open with a destination-count header (`חבילות סים וירטואלי ל-44 יעדים:`). Deals append in the same dash style. This exact format is customer-facing; the operator relies on it.

**Topup rows use fixed canonical slots** `[1,2,3,5,7,10,15,20,25,50]` GB, sorted ascending, with **red dashed rows for sizes the current SIM type lacks** (`X גיגה – לא קיים`). Every row shares one fixed grid (`text | deal-slot(118px) | 🔗 | 📋 | qty | קבע`) so nothing shifts when switching V1/V2/V3 — the operator navigates by muscle memory. Do not "clean up" the red rows or make columns content-sized; positional stability is the feature. The list itself is a fixed two-column grid (no `auto-fill`).

**ICCID → SIM-type detection needs 13-digit prefixes for the 894801-family.** Empirically, 12 digits are ambiguous: `894801000001…` opens both V3 (`…14…`) and V2 (`…12…`) cards. The table `ICCID_TYPE_PREFIXES` holds prefixes at whatever length disambiguates (6 for V1's `894310`, 6 for `893720`→V2, 10 and 13 for the rest); longest match wins; unknown prefixes return `null` and **must not** auto-switch. Auto-switching fires only on a full ICCID (≥18 digits) to avoid flicker while typing, and shows a toast. When new card ranges appear, add sample-derived rows to this table.

**Zone/price caches self-heal.** Manual-site scans persist per-ISO in `globalCache`, each entry stamped with `assignedZone` and `cachedAt`. On load, entries are dropped when re-zoned (recorded zone ≠ current get-countries zone) or older than `GLOBAL_CACHE_TTL_MS` (12h). Expired same-zone entries are retained in `globalCachePrev` purely as baselines for the price-change diff banner. Never load persisted price data without this validation — stale-cache bugs (Singapore showing old-zone prices) happened twice before the validation existed.

## 5. UI architecture

**Top bar** (48px, ink-dark): brand chip, country search with suggestions dropdown, selected-country chips strip (horizontal scroll, never wraps), clear-all button, then the option cluster — רוקן עגלה toggle, כמות, custom `$` amount (Enter recomputes), editable `₪/$` rate, פישוט master toggle, JSON export. All inputs inside the bar carry explicit dark-theme colors *including their `:focus` states* — see §10.

**Tabs** (keys **1–4**, ignored while typing in any field; active tab persisted): `basic` תוכניות בסיסי (manual-site comparison + price-change banners + zone note), `gigaboost` (generic chooser strip + both quick-order cards), `copy` העתקות (reference strip: credit-per-GB, physical credit, wallet, custom amount — the first two with ✎ editable $/₪ tiers), `topup` (scanner, batch mode, canonical-slot package rows). `renderAll` builds only the active tab. The tab IDs live in `TAB_IDS`; the keydown handler is document-level.

**Cart**: floating FAB with live item-count badge → right-edge slide-in drawer (`#cartDrawer`, hidden via `translateX(105%)` — explicit right-side positioning because the app's RTL comes from CSS `direction`, so `[dir]` attribute selectors do not match). Cart mutations all funnel through `renderAll`, which syncs the badge.

**Quote system**: 💬 on both gigaboost cards copies a WhatsApp-ready quote rendered from an editable template (✎ opens a modal). Placeholders: `{country}`, `{esim_plans}`, `{psim_plans}`, `{date}`. Template persists per browser.

**Standalone order portal**: order links carry an encoded `order_payload`; when present, the page boots in `body.order-mode`, which hides the top bar, tabs, FAB, and drawer, and shows only the runner card. Any new chrome you add must be appended to the `body.order-mode … { display:none }` selector list.

## 6. State and persistence

In-memory state of note: `data[]` (countries), `selected[]`, `activeTab`, `cartSettings {emptyCart, quantity}`, `simplifyState {key: bool}` (default true — `isSimplified` treats anything `!== false` as on), `orderBuilderItems[]`, `orderPackageRegistry` (**rebuilt from scratch on every render** — only the visible tab's packages are registered; cart items are immune because they carry their own `checkoutUrl`), `topupState` (ICCID, version, batch fields, catalogs), `globalCache` / `globalCachePrev`, `USD_TO_ILS`, `quoteTemplate`, `refEdit`.

`localStorage` keys:

| Key | Contents |
|---|---|
| `simtlv_session_v1` | Session: selected ISOs, active tab, cart settings, simplify states, **cart items**, batch mode/raw. Written by `persistSession()` at the end of every `renderAll`; restored at boot by `restoreSession()` (guarded by `sessionRestoring` to avoid write-during-restore). |
| `simtlv_global_cache_v7_zone_validated` | Per-ISO manual-site scans, zone-stamped + timestamped. 12h TTL. |
| `simtlv_ref_overrides_v1` | Edited $/₪ tiers for the wallet/physical reference cards (mutates the `WALLET`/`PHYSICAL` arrays in place; defaults kept in `DEFAULT_*`). |
| `simtlv_usd_rate` | Editable exchange rate (default 3.3). |
| `simtlv_quote_template_v1` | Quote template text. |
| `simtlv_topup_cache_v2_preload_20260529` | Topup catalog cache. |
| `simtlv_topup_catalog_by_version_v1_20260529`, `simtlv_topup_auto_catalog_v4_zone_v2_germany_v1_20260529`, `simtlv_topup_auto_state_v4_20260529` | Per-version/auto-preload topup catalogs and state. |
| `simtlv_topup_customer_iccid_20260529`, `simtlv_topup_selected_version_20260529`, `simtlv_topup_iccid_inventory_v2_defaultseed_20260529` | Last customer ICCID, chosen SIM version, known-ICCID inventory. |

Convention: when you change a persisted structure incompatibly, **rotate the key suffix** rather than migrating in place — every operator's stale copy is then ignored on next load. This was done deliberately at `…v7_zone_validated`.

## 8. Testing

A jsdom smoke harness lives outside the HTML (developer machine only): `smoke.js`, with `jsdom` and `acorn` as dev dependencies. **45 tests, all green at v5.6.** Run:

```bash
cd <harness dir> && npm i --no-bin-links jsdom acorn acorn-walk
node smoke.js          # points at the HTML file by path; update via sed on version bump
```

How it works: boots the full file in jsdom with a **stubbed `fetch`** returning realistic API shapes (three country lists — deliberately including a country whose pSIM zone differs from its eSIM zone — plus per-zone package payloads with `id` fields), stubs `alert`/`window.open`/`requestAnimationFrame`, waits ~800ms for init, then drives the app. Because top-level `let` bindings aren't on `window`, tests use a `G(expr)` helper (`window.eval`) to read/poke state. The final test is async: it stubs `sleepOrder`, runs the order runner with 3 items, and asserts exactly one `window.open` plus N−1 navigations.

Coverage highlights: boot/data/selection; REUP and probe-ISO rules; ICCID/qty/empty_cart URL grammar; composite cart keys and 3-ICCID flows; payload roundtrip; **deal no-multiplier** (cart, base, buttons); mixed-zone filtering; cache validation (re-zoned/expired/unknown/unstamped); rate/pricing-editor persistence; quote template placeholders; session restore; tabs + shortcuts; direct/multi-country/generic payment URLs; canonical-slot ordering and red rows; all 16 ICCID samples; region grouping and count headers.

**Process rule: run the suite after every significant change, and add a regression test with every bug fix.** When testing rendered output that includes copy buttons, scope string assertions to the rows section — the copy button embeds the full price text in its `onclick`, which has produced false test failures before.

There is also a dead-code workflow used during refactors: extract the main script, parse with acorn, build a call graph rooted at top-level statements and any function name appearing in string/template literals or HTML, and remove unreachable functions. Conservative by construction; re-parse after stripping.

## 9. Conventions

**Versioning** is strict: every delivered change bumps the **minor** (5.5 → 5.6); after x.9 roll to the next major (4.9 → 5.0); a major redesign may jump the major. Never label anything "final", never suffix like `v3_fix`. Filename pattern: `simtlv_giga_calculator_generated_by_claude_YYYY-MM-DD_vX.Y.html` — keep the pattern, updating the date on new work sessions.

**Language**: all UI strings Hebrew; layout RTL. Prices display in ILS everywhere (eSIM USD × `USD_TO_ILS`). Numbers use `font-variant-numeric: tabular-nums`.

**Workstyle expectations from the owner**: direct implementation over clarifying questions; compact dense UI; positional stability over dynamic layouts; when a judgment call is made, flag it explicitly in the delivery note. Explicitly rejected ideas — do not resurrect without asking: hosting the file (GitHub Pages etc.), order logging, automatic deal-splitting (WooCommerce handles it).

**Validation before delivery**: `node --check` on every extracted `<script>`, CSS brace-balance count, then the smoke suite.

## 10. Known gotchas (each has bitten before)

**CSS layering/specificity.** The stylesheet is layered, and equal-specificity rules resolve by order. Real incidents: a generic `input:focus { background:#fff }` late in the sheet turned top-bar inputs white-on-white the moment they were focused; `.tb-options .opt-btn.is-on` lost its background to a later `.opt-btn.is-on`; the suggestions dropdown inherited the top bar's near-white text onto its white background. Rule of thumb: anything rendered inside the dark top bar needs explicit `color` *and* explicit `:focus` colors; new overrides go into the density layer at the end, and remove superseded rules instead of stacking a third layer.

**RTL specifics.** `[dir="rtl"]` attribute selectors don't match (direction is set via CSS). Tooltips and drawers must be anchored with physical `right`/`left`, not logical `inset-inline-*`, when the intent is "open toward the reading direction". The cart drawer hides at `translateX(105%)` (off the right edge).

**Popup discipline.** One `window.open` per user gesture, total. Any new multi-navigation feature must reuse the single named window pattern from `startGeneratedOrderItems`.

**Registry lifetime.** `orderPackageRegistry` is wiped each render and only repopulated for the visible tab. Never store a registry key for later use across renders/tabs; store the resolved URL and metadata on the cart item instead (this is why cart items are self-contained).

**Focus vs re-render.** `renderAll` recreates inputs; calling it from an `oninput` handler destroys the field mid-typing. The ICCID and batch inputs deliberately avoid re-render on input (the batch counter updates via direct DOM). Preserve that pattern for any new live-typed field.

**`file://` clipboard.** `navigator.clipboard` is unavailable on `file://`; `copyText` falls back to a hidden textarea + `execCommand("copy")`. Don't replace it with clipboard-API-only code.

**Copy buttons embed their payload.** The `onclick='copyText(${JSON.stringify(text)})'` pattern means the full copy text exists inside the HTML attribute. Harmless at runtime, but it affects string-matching in tests (§8) and means very large copy payloads inflate the DOM.

**Zone semantics.** Before "fixing" a zone discrepancy, check all three zone sources for that country — the APIs genuinely disagree with each other by SIM type (Singapore precedent), and the calculator's job is to *display* each catalog's truth, clearly labeled, not to reconcile them.

## 11. Extension points

Deliberately easy to extend, in rough order of likelihood:

* **New ICCID ranges** → add `{ prefix, type }` rows to `ICCID_TYPE_PREFIXES` (prefix as long as needed to disambiguate; longest wins). Add the samples to the detection test.
* **Region adjustments** → `REGION_ISOS` (space-separated ISO lists per Hebrew region name) and `REGION_ORDER` for display order. Unmapped ISOs fall into "אחר".
* **Canonical topup sizes** → `CANONICAL_TOPUP_GBS` inside `renderTopupProducts`. Present-but-non-canonical sizes are appended automatically; missing canonical sizes go red.
* **Quote default** → `DEFAULT_QUOTE_TEMPLATE`; new placeholders are added in `buildQuoteText`'s `replaceAll` chain (document them in the modal's legend).
* **Pricing tiers** → `WALLET` / `PHYSICAL` arrays are runtime-editable via the ✎ editors; only touch the defaults (`DEFAULT_WALLET` / `DEFAULT_PHYSICAL`) in code.
* **New persisted structure** → new `simtlv_*` key with a versioned suffix; wire into `persistSession`/`restoreSession` only if it's per-session state rather than a standalone store.
* **New tab** → extend `TAB_IDS`, add a nav button with the next digit `<kbd>`, add a branch in `renderAll`, and include the tab in the session restore whitelist.

## 12. Quick triage recipes

*"Prices look stale / wrong zone"*: open devtools → Application → localStorage → delete `simtlv_global_cache_v7_zone_validated` (or just wait out the 12h TTL). If it recurs, check whether the country was re-zoned upstream (`/get-countries` vs the per-type lists) — the zone now prints on every card label, so compare labels first.

*"An order placed the wrong quantity"*: almost certainly a deal/quantity interaction. Inspect the cart item (`source`, `isBase`, `qty`) and the URL from `buildOrderItemUrl`; a deal URL must not carry `quantity>1`.

*"Middle items missing from a multi-item order"*: popup blocking. Confirm the browser allowed the single background window; the runner alerts if it couldn't open at all.

*"Copy button does nothing"*: on `file://`, confirm the `execCommand` fallback path executes; if the button lives in a new card layout, verify `copySection`'s `closest(".block")` still finds the `<pre>`.

*"Something moved in the topup grid"*: check that the canonical-slot rendering and the fixed row grid (`grid-template-columns` on `.topup-line`) weren't altered, and that packages are still sorted by GB before slotting.
